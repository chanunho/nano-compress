# NanoCompress Unified Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single-file H.264 script with a stdlib-only Python CLI that produces the smallest practical MP4 at a user-chosen resolution, plays by default on modern phones and desktops, and handles single files or folders.

**Architecture:** A thin `compressor.py` CLI parses options into an immutable `Options` object and plans jobs. A small `nanocompress` package holds focused modules: settings/validation, ffprobe metadata parsing, FFmpeg command construction, job discovery/naming, and execution/summaries. Every module is unit-testable without media; integration tests use short synthetic clips generated by FFmpeg.

**Tech Stack:** Python 3.8+ standard library (`argparse`, `dataclasses`, `json`, `subprocess`, `unittest`), FFmpeg/ffprobe (`libx265`, `libx264`, `aac`, `hqdn3d`, `yadif`, `zscale`, `tonemap`).

**Spec:** `docs/superpowers/specs/2026-10-29-nanocompress-pipeline-design.md`

## Global Constraints

- Python 3.8+; standard library only; no third-party pip dependencies.
- Requires `ffmpeg` and `ffprobe` on `PATH`; no other external tools.
- Output is always MP4 with `-movflags +faststart`.
- Default encoder is HEVC via `libx265`, tagged `-tag:v hvc1`; H.264 via `libx264` is opt-in.
- Default resolution `240`; allowed values `144,160,180,216,240,288,320,360,480,540,720`.
- Default preset `slow`; allowed `ultrafast,superfast,veryfast,faster,fast,medium,slow,slower,veryslow`.
- Quality→CRF: HEVC `quality=24, balanced=28, small=32`; H.264 `quality=21, balanced=25, small=29`.
- Audio is always AAC in MP4; default bitrate `64k`; preserve all audio tracks.
- Text subtitles become `mov_text`; image-based subtitles are skipped with a warning.
- Never overwrite the input file; write to a `.part.mp4` temp then rename on success.
- HDR is preserved by default; `--tonemap` converts to SDR BT.709; H.264 + HDR auto-tone-maps.
- Batch mode processes sequentially, continues after failures, and exits non-zero if any job failed.

## Review Focus

1. HDR source: preserved as 10-bit HDR by default; `--tonemap` yields 8-bit SDR BT.709; H.264+HDR auto-tone-maps. Tested in Tasks 2 and 3.
2. Anamorphic or rotated source: output has square pixels and correct display aspect, never stretched or sideways. Tested in Tasks 3 and 5.
3. Interlaced source: deinterlaced with `yadif`; progressive sources untouched. Tested in Task 3.
4. Folder with nested dirs, name collisions, and existing outputs: mirror tree, numeric suffix on collision, skip existing unless `--overwrite`, prune output dir. Tested in Task 4.
5. Corrupt file in a batch: reported, run continues, non-zero exit; image subtitles skipped with a warning. Tested in Tasks 3, 5, and 6.

import unittest
from nanocompress.settings import Options
from nanocompress.probe import MediaInfo, Subtitle
from nanocompress.command import (
    EncodeJob, should_tonemap, parse_sar, target_width,
    build_filters, resolve_pix_fmt, build_command,

def media(**kw):
    base = dict(duration=60.0, width=842, height=456, video_codec="hevc",
                sample_aspect_ratio="2105:2109", rotation=0,
                color_transfer="bt709", color_primaries="bt709",
                is_hdr=False, is_interlaced=False, audio_tracks=1, subtitles=())
    base.update(kw)
    return MediaInfo(**base)

def job(media_info=None, options=None, out="/tmp/out.mp4"):
    return EncodeJob("in.mp4", out, media_info or media(), options or Options())

        self.assertTrue(should_tonemap(m, Options(encoder="h264")))
